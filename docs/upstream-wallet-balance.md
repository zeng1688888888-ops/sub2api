# 上游钱包余额

账号管理的“上游渠道声明”在倍率下方显示上游账号余额，例如 `1.50x` / `余额 $8,465.83`。适用于使用 API Key 接入、支持 Sub2API 倍率和用量接口的上游。

点击原刷新按钮会同时更新倍率和余额；后台沿用现有上游倍率探测开关和周期，不新增定时任务。新增字段保存在 `accounts.extra.upstream_billing_probe.balance`，无需数据库迁移。

成功读取 `GET /v1/sub2api/billing` 后，使用同一上游地址、API Key、请求头设置、代理和 TLS 配置读取 `GET /v1/usage?days=1`。仅接收明确的 `mode=unrestricted`、`isValid=true`、数值 `balance` 和三字母货币代码 `unit`。不会把 `remaining`、API Key 限额、订阅额度或本地账号额度当作钱包余额。

余额查询只用于展示，不修改倍率、余额、额度或调度决策。真实零余额显示为 `$0.00`。上游不支持或不提供钱包余额时显示“未提供”；首次尚未获取显示“未获取”。查询失败不影响已成功取得的倍率；保留的旧余额或过期余额标注“历史值”，悬停可见获取时间。

余额请求最多五秒，且受同次倍率探测的十秒总超时约束。响应最多 64 KiB，禁用重定向，不跟随上游响应中的 URL，不持久化账户资料、完整响应或凭据。修改上游身份后旧余额随倍率快照一同清除。
