# 单账号多出口并发

在 **账号管理 → 编辑 OpenAI 账号 → 多出口并发** 中启用。先在代理管理添加不同出口的代理，然后为账号选择多个代理并分别填写并发上限。该配置使用同一个账号的凭据，不会创建或复制上游账号。

例如：账号总并发 100，三个出口各设 5，配置允许同时处理最多 15 个相关请求；列表在总并发下显示各出口的当前占用 / 上限。鼠标悬停可查看代理名称。若需要配置 200，可使用十个各设 20 的出口，同时将账号总并发设为至少 200。这里是本地调度额度，真实成功吞吐仍需对目标上游进行测试。

## 调度行为

- 每次请求选择当前占用比例较低且仍有空位的出口，Redis 原子占位，多个服务实例共享计数。
- 账号原有总并发、用户并发、配额和上游错误处理继续生效。有效容量不超过账号总并发与出口容量之和的较小值。
- 一个逻辑请求及其内部重试固定使用同一出口；不修改共享账号快照。
- 请求结束或失败会释放出口名额。长请求每 20 秒续期，进程异常退出后的名额最多保留 90 秒。无法续期时取消请求。
- 停用、过期或已删除的代理不会被选中；全满或全不可用时按现有网关故障转移流程处理，不自动回退直连。
- 原有单代理配置继续用于认证刷新、测试及维护操作。
- 计数读取失败显示 `?`，而不是误报为零。

## 支持范围

当前支持非影子 OpenAI 账号的 Responses（包括已有 BPS Responses 分流）、Chat Completions、Messages、图片、Embeddings 和 Alpha Search 转发。Responses WebSocket 入站在原有 WebSocket 允许策略内使用 HTTP 桥接，每轮独立分配出口。未启用多出口的账号沿用现有行为。Realtime/Live、计数预检、登录及维护请求不使用出口池。

一组代理不一定对应不同公网 IP；请在代理管理中检测出口地址。账号或模型的上游额度不会因增加代理而改变。

## 配置与接口

配置保存在 `accounts.extra.openai_egress_pool`，无需新增数据库迁移。管理员创建或更新账号可提交：

```json
{
  "extra": {
    "openai_egress_pool": [
      { "proxy_id": 11, "concurrency": 5 },
      { "proxy_id": 12, "concurrency": 5 },
      { "proxy_id": 13, "concurrency": 5 }
    ]
  }
}
```

每个出口并发为 1–2000 的整数，最多 32 个出口，不允许重复代理 ID。提交空数组关闭；更新其他 extra 字段时省略该键会保留已有配置。暂不支持批量修改出口池。

完整和精简账号列表以及账号详情返回 `egress_statuses`，包含代理 ID、名称、上限、当前占用及可用状态，不包含代理密码或 URL。列表刷新会检测出口变化，即使总并发不变也会更新。

账号备份导出在包含代理时使用可迁移的 `egress_pool[].proxy_key`；导入时映射到目标实例的新代理 ID。选择不导出代理时，也不导出出口池绑定。原始数据库 ID 格式的出口池不能直接跨实例导入。

## 验证

自动化测试覆盖原子容量限制、不同账号隔离、负载比例分配、释放及过期恢复、无代理回退、配置校验、嵌套调用、Codex/BPS/WebSocket 桥接转发、备份重映射和前端配置/容量展示。界面预览中的 13/100 和 5/5、4/5、4/5 为演示数据，不是上游压测结果。
